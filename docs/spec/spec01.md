# 見守りアプリ 全体設計書

## 1. 企画概要

離れて暮らす親の生存確認と、子から親への近況共有を1つにまとめたサービス。

親の家に M5Stack Core2 と赤外線センサーを設置する。親がセンサーの前を通ると、
子のスマホに通知が届く。一定時間反応がなければ警告を出す。
子が撮った写真は1日1回 Core2 に表示され、親はボタンでいいねを返せる。

### 解決する課題
- 離れて暮らす親に何かあったとき、子が気づくのが遅れる
- 毎日の安否確認の連絡は、双方に負担がかかって続かない

### 特徴
- 親側の操作は「通る」と「ボタンを押す」だけ
- 通知が来ないことが正常、という設計
- 一方的な監視ではなく、写真といいねで双方向になっている

## 2. 構成要素

| 要素 | 技術 | 役割 |
|---|---|---|
| フロント | React (PWA) | 子が使う。写真の投稿・管理、通知の受信 |
| バック | Cloudflare Workers | API、定期実行(日次切替・警告判定) |
| DB | Supabase (Postgres + Storage) | データと画像の保管 |
| ハード | M5Stack Core2 + 赤外線センサー | 検知、写真表示、いいね |

```
┌─────────────────┐                    ┌─────────────────┐
│  フロント         │                    │  M5Stack Core2   │
│  React / PWA    │                    │  + 赤外線センサー  │
└────────┬────────┘                    └────────┬────────┘
         │                                      │
         │ ① 画像投稿                            │ ⑥ 通過検知
         │ ② 画像リスト取得                       │ ⑦ いいね
         │ ③ 並べ替え・削除                       │ ⑧ ポーリング
         │ ④ 設定変更                            │   (ハートビート兼用)
         │ ⑤ 通知受信(Web Push)                   │
         ▼                                      ▼
┌──────────────────────────────────────────────────────┐
│  バックエンド (Cloudflare Workers)                       │
│   HTTP API / Cron(10分ごと)                            │
└────────────────────────┬─────────────────────────────┘
                         ▼
┌──────────────────────────────────────────────────────┐

│   Postgres: devices / images / detections / likes      │

└──────────────────────────────────────────────────────┘
```

## 3. 主要な仕様

### 生存確認
- センサー反応時、リセット後の初回だけ子に通知する
- リセット間隔は初期値12時間(1日2回まで通知)
- 最終検知から12時間経過で警告を出す
- 警告は「親が動いていない」と「デバイスが落ちた」を区別する
- 誤検知(ペット・来客)は当面考慮しない

### 写真表示
- 子が投稿した写真を、古い順に1日1枚ずつ Core2 に表示する
- 切り替えの時刻は子アプリで設定できる
- 在庫がなければ前日の表示を継続する
- 切り替え時、子に「どこまで表示されたか」を通知する
- 親には通知しない(Core2 を見る習慣をつけるため)

### 画像
- 子アプリで切り取り位置を指定する(4:3)
- 原寸(長辺1600px)と表示用(320×240)の2つを保存する
- 切り取り座標も保存し、切り直しの初期値に使う
- Core2 は表示用、アプリの一覧は原寸を表示する

### いいね
- 親が Core2 のボタンを押すと、子に通知が届く
- Core2 は送信結果を見てから画面表示を確定する
- いいね時に表示中だった画像を記録する

### テストモード
- 子アプリの隅にある小さなトグルで切り替える
- リセット間隔は1秒、ポーリング間隔は5秒になる
- オン時は表示の色を変え、切り忘れに気づけるようにする

## 4. 通信一覧

| # | 方向 | 契機 | 頻度 |
|---|---|---|---|
| ① | フロント → バック | 投稿操作 | 1日数回 |
| ② | フロント → バック | 画面表示時 | 不定 |
| ③ | フロント → バック | 並べ替え・削除 | 稀 |
| ④ | フロント → バック | 設定変更 | 稀 |
| ⑤ | バック → フロント | イベント発生時 | 1日数回 |
| ⑥ | M5Stack → バック | センサー反応 | 1日数十回 |
| ⑦ | M5Stack → バック | ボタン押下 | 1日0〜数回 |
| ⑧ | M5Stack → バック | 定期 | 通常10分 / テスト5秒 |

画像バイナリは Storage の署名付き URL で直接やりとりする。
Workers を通るのは JSON のみ。

## 5. MVP の範囲

### 含む
- 通過検知 → 子への通知
- 最終検知から12時間経過 → 警告
- デバイス無応答 → 警告
- 写真の投稿・切り取り・並べ替え・削除
- 1日1回の表示切り替えと進捗表示
- いいね
- テストモード

### 含まない
- ログイン、ID入力(device_id / user_id はカラムだけ用意し固定値を入れる)
- 親側アプリ
- M5Stack の画面切り替え(カレンダー・天気など)
- 親への通知
- 誤検知の判別

MVP は親1台・子1人の固定構成とする。
将来の拡張に備え、全テーブルに device_id / user_id を最初から持たせる。

## 6. 設計上の判断

| 判断 | 理由 |
|---|---|
| リセット判定をサーバー側に置く | 再起動で状態が飛ばず、間隔変更にファーム更新が不要 |
| ポーリング応答に次回間隔を含める | テストモード切替をファーム更新なしで行う |
| last_detected_at と last_seen_at を分離 | 親の無活動とデバイス障害を区別する |
| 切替ロジックを1関数に閉じる | 日めくりの方式を後から差し替えられる |
| 原寸と表示用の2枚を保存 | Core2 のメモリ制約を回避しつつ、切り直しも可能にする |
| 画像を Storage 直送 | Workers の実行時間と転送コストを使わない |
| sort_order を double | 並べ替えの UPDATE を1行に抑える |
