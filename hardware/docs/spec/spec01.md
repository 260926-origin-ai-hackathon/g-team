# ハードウェア設計書 (M5Stack Core2 + 赤外線センサー)

## 1. 構成

| 部品 | 用途 |
|---|---|
| M5Stack Core2 | 表示、いいね入力、通信 |
| 赤外線センサー(PIR) | 人の通過検知 |

- 電源は常時接続。deep sleep は使わない(画面を表示し続けるため)
- Wi-Fi は起動時に接続し、以降は維持する

---

## 2. 保持する状態

```
current_image_id : 表示中の画像ID(ポーリングの差分判定に使う)
next_poll_sec    : サーバーから受け取る次回間隔
last_sent_at     : 最後に検知を送った時刻(連続送信の抑制用)
like_state       : none | sending | ok | error
```

**リセット判定の状態は持たない。** サーバー側が判定する。
デバイスに持たせると再起動で飛び、間隔変更にファーム更新が必要になる。

---

## 3. メインループ

```
【起動時】
  Wi-Fi 接続
  ポーリング1回 → 画像を取得して表示

【ループ】
  1. Wi-Fi 接続状態を確認。切れていたら再接続
  2. センサー割り込みあり?
       → last_sent_at から30秒以上経過していれば POST
  3. ボタン押下あり?
       → いいね POST → 結果を見て画面表示を確定
  4. next_poll_sec 経過?
       → ポーリング GET
       → changed なら画像を取得して描画
```

### Wi-Fi の扱い(重要)

毎回 `WiFi.begin()` から接続し直すと、IPが振られるまでに数秒かかる。
テストモードの5秒間隔では、接続が終わる前に次の周期が来る。

```
✕ ループ内で WiFi.begin() → リクエスト → WiFi.disconnect()
○ 起動時に一度 WiFi.begin()。以降はHTTPリクエストのみ
```

ループ先頭で `WiFi.status()` を確認し、
`WL_CONNECTED` でなければ再接続する。

---

## 4. センサー

### 接続
PIR センサーの出力を GPIO に接続し、立ち上がりで割り込みを取る。

### 連続検知の抑制
人が通ると PIR は数秒間 HIGH を維持し、
その場に留まれば反応し続ける。

**デバイス側では30秒の抑制のみ行う。**
「リセット後の初回か」の判定はサーバーが行うため、
デバイスは単純な間引きだけでよい。

```
割り込み発生
  ↓
now - last_sent_at >= 30秒 ?
  ├ YES → POST /devices/{id}/detections
  │        last_sent_at = now
  └ NO  → 何もしない
```

### 送信失敗時
リトライしない。次の検知で送られるため、取りこぼしても問題にならない。
ログだけ残す。

### 誤検知
ペットや来客にも反応するが、MVP では考慮しない。

---

## 5. いいね

Core2 の物理ボタン(A/B/C のいずれか)に割り当てる。

```
ボタン押下
  ↓
like_state = sending / 画面に「送信中」を表示
  ↓
POST /devices/{id}/likes { "image_id": current_image_id }
  ├ 成功 → like_state = ok    / 「送信済」を表示(数秒後に戻す)
  └ 失敗 → like_state = error / 「送信できませんでした」を表示
```

**送信結果を待ってから確定表示する。**
先に成功表示を出すと、失敗したときに嘘になる。

同じ画像に何度も押せる。制限はサーバー側でも設けない。

---

## 6. 画像の表示

### 取得
ポーリングのレスポンスに含まれる署名付きURLから
display_path の画像(320×240 JPEG、20〜40KB)を取得する。

**Core2 側でのリサイズ・切り抜きは行わない。**
フロントで生成済みのものをそのまま描画する。
Core2 のメモリでは大きな JPEG のデコードが厳しいため。

### 描画
```
┌────────────────────┐
│                    │
│       写真          │  320×240
│                    │
│                    │
├────────────────────┤
│  ♥ ボタンA  [送信済]  │  いいねのフィードバック
└────────────────────┘
```
画像は画面いっぱいに描画し、下部にいいねの状態を重ねる。

### 取得失敗時
前の画像を表示し続ける。current_image_id は更新しない。
次のポーリングで再試行される。

---

## 7. ポーリング

```
GET /devices/{device_id}/display?current={current_image_id}

変化なし → { "changed": false, "next_poll_sec": 600 }
変化あり → { "changed": true, "image_id": "...", "url": "...",
             "next_poll_sec": 600 }
```

- 間隔は **サーバーから受け取った next_poll_sec に従う**。
  デバイス側に固定値を持たない
- テストモードでは 5 が返る。ファーム更新なしで切り替わる
- このリクエストが届くことで、サーバー側の死活監視が成立する

### 失敗時
next_poll_sec の間隔を維持したまま再試行する。
連続で失敗し続けると、サーバー側で30分後に
device_offline の警告が子に飛ぶ。

---

## 8. 設定値

ファームに直書きする項目(MVP)。

| 項目 | 値 |
|---|---|
| Wi-Fi SSID / パスワード | 直書き |
| サーバーURL | 直書き |
| device_id | 直書き(固定値) |
| 検知の抑制時間 | 30秒 |
| 初回ポーリング間隔 | 600秒(以降はサーバー指定) |

Wi-Fi のプロビジョニング画面は作らない。

---

## 9. 通信まとめ

| # | 内容 | 契機 | 頻度 |
|---|---|---|---|
| ⑥ | 通過検知 POST | センサー反応 | 1日数十回 |
| ⑦ | いいね POST | ボタン押下 | 1日0〜数回 |
| ⑧ | ポーリング GET | 定期 | 通常10分 / テスト5秒 |
| - | 画像取得 | ⑧で changed=true | 1日1回 |

1日の通信量は画像1枚ぶん(20〜40KB)が大半。
それ以外は数KB程度。
