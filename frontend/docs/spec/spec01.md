# フロントエンド設計書 (React / PWA)

## 1. 前提

- React + Vite の PWA。Cloudflare Pages にデプロイ
- 利用者は子のみ。スマホでの利用を想定
- MVP では認証なし。device_id / user_id は固定値

### iOS の制約(重要)
Web Push は iOS 16.4 以降で使えるが、**ホーム画面に追加されていないと
通知が届かない**。初回起動時に追加を促す案内を必ず出す。
警告通知が企画の核心なので、ここが機能しないと成立しない。

## 4. 画像の投稿処理

投稿はフロントで完結させる。サーバーに画像処理を持ち込まない。

```
1. ファイル選択(<input type="file" accept="image/*">)
     ↓
2. react-easy-crop で 4:3 の枠を指定させる
   - Core2 の画面比に固定
   - 切り取り座標 { x, y, width, height } を取得
     ↓
3. canvas で2枚を生成
   - 原寸 : 長辺1600pxにリサイズ、JPEG quality 0.85(数百KB)
   - 表示用: 切り取り範囲を 320×240 に縮小、JPEG quality 0.8(20〜40KB)
     ↓
4. 2枚 + 座標を multipart で送信
```

### 実装の要点
- 元画像が数MBあるため、canvas 処理はメインスレッドを止める。
  処理中はローディングを出す
- iOS の Safari は canvas サイズに上限があるため、
  長辺1600pxへの縮小を先に行ってから切り抜く
- EXIF の回転情報を無視すると横向きになる。
  `createImageBitmap(file, { imageOrientation: 'from-image' })` で吸収する

### 切り直し
保存済みの座標を react-easy-crop の初期値に渡す。
表示用画像だけを作り直して差し替える(原寸は再利用)。

---

## 5. 並べ替え・削除

### 並べ替え
dnd-kit でドラッグ&ドロップ。
**中間値の計算はサーバーが行う。** フロントは位置だけ伝える。

```
PATCH /devices/{device_id}/images/{image_id}
  { "after_image_id": "..." }   ← この画像の直後に置く
  { "after_image_id": null }    ← 先頭に置く
```

- 表示済み(status=displayed)は並べ替え対象外
- 楽観的更新でUIを先に動かし、失敗したら元に戻す

### 削除
論理削除。確認ダイアログを出す。
表示済みのものは履歴として残すため、削除させない。

---

## 6. 通知の受信

```
1. 初回起動時、通知の許可を求める
   - iOS はホーム画面追加を先に案内する
2. Service Worker を登録
3. Push 購読を作成し、サーバーに送る
4. Service Worker で push イベントを受け、通知を表示する
```

### 通知の種類と表示

| type | 表示 | 優先度 |
|---|---|---|
| detection | 「反応がありました」 | 通常 |
| warning / no_detection | 「12時間、反応がありません」 | 高 |
| warning / device_offline | 「デバイスと通信できません」 | 高 |
| like | 「いいねが届きました」 | 通常 |
| display_changed | 「今日の写真が表示されました」 | 低 |

warning は `requireInteraction: true` を付け、消えないようにする。

---

## 7. データ取得

TanStack Query を使う。

| クエリ | 更新契機 |
|---|---|
| 画像リスト | 画面表示時、投稿後、通知受信時 |
| ステータス | 画面表示時、30秒ごと |

- 画像リストは `status=all` で一括取得し、クライアントで分類する
- 画像URLは署名付き。有効期限が切れるため、
  画面を開いたままにする場合は再取得する

---

## 8. 設定画面

| 項目 | 初期値 | 保存先 |
|---|---|---|
| 切替時刻 | 00:00 (JST) | サーバー |
| 通知の許可 | - | ブラウザ |
| テストモード | off | サーバー |

### テストモードのトグル
- ホーム画面の右上に小さく薄く配置する
- **オン時は色を変え、常に状態が見えるようにする**
  切り忘れると Core2 が5秒間隔でポーリングし続ける
- オン時は「切替を今すぐ実行」ボタンも表示する

---

## 9. 状態管理

```
サーバー状態   : TanStack Query(画像、ステータス、設定)
ローカル状態   : useState(トリミング中の座標、UIの開閉)
永続化するもの : なし(Push購読はブラウザが持つ)
```

localStorage は使わない。
表示すべき状態はすべてサーバーが持つ。
